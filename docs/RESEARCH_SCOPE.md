# Research scope and terminology

## What “design” means here

In this blueprint, “design” names an orchestration API. It does not mean that a
candidate has a desired structure or function, nor that it is safe to synthesize.
A computational candidate is a hypothesis until independently tested under an
appropriate governance and experimental framework.

## Evidence ladder

1. **Schema validity:** inputs and outputs conform to software contracts.
2. **Computational integrity:** algorithms reproduce declared benchmarks.
3. **Predictive evidence:** prospective tests support a narrow claim.
4. **Experimental evidence:** suitable assays validate that claim.
5. **Application evidence:** domain-specific safety and efficacy requirements.

This repository reaches only the first level for its implemented scaffolding.

## Vocabulary

- **Backbone candidate:** an opaque coordinate hypothesis.
- **Sequence candidate:** an opaque proposed residue string linked to a backbone.
- **Scorecard:** separate metric values plus provenance and uncertainty.
- **Rank:** the output of a declared policy, not proof of quality.
- **Human review:** an explicit authorization gate, not a cosmetic checkbox.
